# KB-012: Service status and duplicate incidents

- Owner: Service Management
- Last reviewed: 2026-08-28
- Status: Active
- Applies to: Shared services and multi-user incidents

Before creating an incident for a shared-service problem, check the current
service-status feed and search open tickets for the same service, symptom,
location, and time window.

If an active incident already matches, link the request to that incident and
provide its public status; do not create a duplicate incident. If there is no
match and multiple users are affected, create a high-priority incident with
the affected service, scope, start time, and observed symptoms.

Do not mark an incident resolved because one user recovers. Resolution requires
the owning team to restore service and update the incident status.
