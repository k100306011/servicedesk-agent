# Cost model

Generated by `python -m eval.cost` from the prompts and replies that B3 really sent and received (242 requests, 484 model calls in `results/llm_calls/`: cost_B3_dev, final_B3, latency_B3).

**This prototype was not run against a live Azure deployment.** The token counts below are estimates: the local model uses the Qwen tokenizer, so every prompt and reply was recounted with the GPT tokenizer `o200k_base` (tiktoken). Both counts are shown.

## Tokens per request (B3: understand + decide)

| Count | Input | Output |
|---|---|---|
| Local model (Qwen tokenizer, from vLLM usage) | 3,295 | 376 |
| Azure estimate (o200k_base: messages ≈ 3 tokens each + 3, plus the JSON schema) | 3,820 | 368 |

- The Azure estimate includes the JSON schema of each call (323 + 273 tokens), because the structured-output schema is added as a prefix to the system message (Microsoft Learn, prompt caching, https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/prompt-caching, page date 2026-09-09, checked 2026-11-24).
- Calls that needed a structured-output retry: 0 of 484.
- Prompt cache today: no benefit. The cache needs an identical prefix of at least 1,024 tokens. The prompts put the per-request random markers near the top, so the identical prefix is only 367 (understand) and 326 (decide) tokens.
- With a reordered prompt (random markers, canary, language and channel moved to the end), about 1,708 input tokens per request become cacheable. That is a production change, not tested here.

Source: https://azure.microsoft.com/en-us/pricing/details/azure-openai/

| Model, deployment | Input | Cached input | Output |
|---|---|---|---|
| gpt-6-luna, Global | 0.1 | 0.01 | 0.5 |

| gpt-6.2-sol, Global | 2.0 | 0.1 | 10.0 |

Formula: `cost per request = input tokens × input price / 1,000,000 + output tokens × output price / 1,000,000`. In the cache columns the cacheable prefix uses the cached-input price; cache-write charges (GPT-5.6 and later) are not modeled.

| gpt-6-luna, Global | $0.0006 | $5.66 | $28.30 | $4.12 | $20.62 |
| gpt-6-luna, Data Zone | $0.0006 | $6.23 | $31.13 | $4.54 | $22.68 |
| gpt-6.2-sol, Global | $0.0113 | $113.21 | $566.03 | $80.75 | $403.77 |
| gpt-6.2-sol, Data Zone | $0.0125 | $124.53 | $622.63 | $88.83 | $444.14 |

A small model (Luna) for all traffic is the floor. A realistic mix sends hard cases to a larger model or uses the model router; the cost then sits between the two rows. Retries, long context and Provisioned Throughput are not modeled.

## Staff time (assumption, not measured)

**Assumption:** the agent saves the desk some minutes of triage per request (reading, classifying, routing, asking for missing facts), because a person only reviews the proposal. The real number must come from shadow mode.

| Minutes saved per request (assumed) | 10,000 requests/month | 50,000 requests/month |
|---|---|---|
| 1 | 167 hours | 833 hours |
| 3 | 500 hours | 2,500 hours |
| 5 | 833 hours | 4,167 hours |

Even the smallest assumption (1 minute) is about 167 staff hours per month at 10,000 requests. Whether that outweighs the model cost depends on the staff cost, which this exercise does not give; make that comparison with the service owner's numbers.
